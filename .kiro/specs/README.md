# 起始页项目规范总览

本项目包含两个独立的规范，分别管理不同阶段的功能开发。

## 规范结构

### 1. 起始页增强功能规范 (`start-page-enhancements/`)

**阶段：** 第一阶段 - 基础功能增强

**功能范围：**
- UI/UX 改进（SVG 图标、圆角优化、字体调整）
- 拖放排序系统
- 国际化支持（中英文切换）
- 时间日期优化（12H/24H 切换、中文格式）
- 右键菜单（编辑、删除）
- 统一设置菜单
- 弹窗布局优化

**文件：**
- `requirements.md` - 16 个需求
- `design.md` - 18 个正确性属性
- `tasks.md` - 19 个主要任务

**状态：** 部分已实现，部分待实现

---

### 2. 用户认证与后端系统规范 (`user-auth-and-backend/`)

**阶段：** 第二阶段 - 用户系统和运营管理

## 实施顺序

### 推荐实施流程

1. **完成第一阶段** - 起始页增强功能
   - 完成所有 UI/UX 改进
   - 实现拖放排序、国际化等基础功能
   - 确保所有测试通过

2. **实施第二阶段** - 用户认证与后端系统
   - 设置后端基础设施
   - 实现 Google OAuth 集成
   - 实现用户数据同步
   - 实现壁纸系统
   - 构建运营后台

### 并行开发建议

- **前端和后端可以并行开发**
  - 前端团队：实现 UI 和客户端逻辑
  - 后端团队：实现 API 和数据库

- **运营后台可以在后端基础完成后开始**
  - 依赖后端 API 的完成

## 技术栈建议

### 前端
- HTML5 + CSS3 + JavaScript (ES6+)
- Google Sign-In 库
- 可选：Chart.js（用于统计图表）

### 后端
- Node.js + Express 或 Python + Flask
- PostgreSQL 或 MongoDB
- JWT 用于会话管理
- Multer（文件上传）

### 运营后台
- React 或 Vue（推荐）
- 或纯 HTML/CSS/JavaScript

### 部署
- Docker 容器化
- AWS/GCP/Azure 云服务
- Nginx 反向代理
- SSL/TLS 证书

---

## 关键集成点

### 前端和后端的集成

1. **认证流程**
   - 前端：Google Sign-In → 获取 ID Token
   - 后端：验证 Token → 创建用户 → 返回 JWT

2. **数据同步**
   - 前端：修改数据 → 发送 API 请求
   - 后端：验证请求 → 保存到数据库 → 返回确认

3. **壁纸系统**
   - 前端：选择壁纸 → 发送选择到后端
   - 后端：保存选择 → 返回壁纸 URL

4. **运营后台**
   - 前端：管理员操作 → 发送 API 请求
   - 后端：验证权限 → 执行操作 → 记录日志

## 常见问题

### Q: 两个规范可以同时开发吗？
A: 可以。前端和后端可以并行开发，但需要定义清晰的 API 契约。

### Q: 如何处理第一阶段和第二阶段的功能冲突？
A: 两个阶段的功能是互补的，不会冲突。第二阶段扩展第一阶段的功能。

### Q: 如何保证数据安全？
A: 使用 HTTPS、JWT 认证、数据加密、速率限制等多层安全措施。

### Q: 如何处理离线用户？
A: 使用本地存储缓存数据，网络恢复时自动同步。
